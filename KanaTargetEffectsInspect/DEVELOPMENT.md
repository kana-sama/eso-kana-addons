# Проверка Kana Target Effects Inspect

## Локальные проверки

Из корня репозитория:

```sh
python3 KanaTargetEffectsInspect/tests/run.py
python3 KanaTargetEffectsInspect/tests/run.py --syntax
```

Стенд использует `lupa.lua51`. Если модуль не установлен, установите `tests/requirements.txt` в отдельное окружение Python либо каталог, указанный в `PYTHONPATH`. Уже существующий каталог `/private/tmp/kana-buff-panels-test-deps` поддерживается также; Lua другой версии не подставляется незаметно.

Тесты запрещают дополнительное чтение эффектов через `GetNumBuffs` и `GetUnitBuffInfo`. Проверяются исходные данные, сохраняемые видимые иконки, наведение/очистка подсказки, продолжение штатного обновления цели, независимость контейнера персонажа, таймеры, повторная выдача контролов и восстановление после ошибки.

Отдельная регрессия воспроизводит реальный порядок штатной клавиши курсора: `OnToggleHUDUIBinding` → `Show(hudui)` → HUD `SCENE_HIDING` → замена `currentScene` → `OnPreSceneStateChange` → `SetInUIMode(true)` → `hudui` `SCENE_SHOWING`. Снимок захватывается при уходе из HUD, пока исходные контролы ещё доступны. Прямой вызов `SetInUIMode` и запоздавшее событие камеры проверяются отдельно.

Результат 2026-10-18: 20/20 тестов аддона, 58/58 тестов соседнего KanaBuffPanels, синтаксис 5 Lua-файлов — без ошибок. Независимое ревью выявило и помогло исправить порядок входа через штатную клавишу курсора.

## Контракты ESO

Сверены исходники API 101051, commit `6639eb2adecc0480557d9068579319919a0c3fe6`: `buffdebuff.lua`, `buffdebuffstyles.lua`, `buffdebuff.xml`, `unitframes.lua`, `ingamescenemanager.lua`, `zo_scenemanager_leader.lua`, `zo_scenemanager_base.lua`, `zo_scene.lua`, `objectpooltemplates.lua`, `ESOUIDocumentation.txt`.

Обёртки стоят только на экземпляре контейнера `reticleover`; оригинальные Update и RefreshContainerVisibility вызываются всегда. Глобальные классы, общий исходный пул и `player` не изменяются. Собственный пул использует `ZO_BuffDebuffIcon`; существующий style object оформляет и обновляет время на копиях без повторного сбора эффектов. Содержимое обновляется на кадре только во время просмотра.

Для штатной клавиши курсора используется callback ухода из HUD. Prehook `SetInUIMode` покрывает вход через сценовый менеджер до начала смены сцены; событие камеры покрывает прямые изменения режима. Снимок показывается только при переходе из `hud` в `hudui`; открытие меню, смена режима ввода, разрешения и локации его сбрасывает. При несовместимом API аддон выводит одно сообщение и оставляет штатный UI работающим.

## Проверка в ESO

После обнаружения и включения аддона выполните один `/reloadui` и проверьте:

1. Навести прицел на цель с бафами и дебафами, включить курсор обычной клавишей и прочитать несколько иконок.
2. Дождаться окончания короткого эффекта: время равно нулю, иконка остаётся до выхода из режима курсора.
3. Выключить курсор, сменить цель и повторить. Без цели старые эффекты не появляются.
4. Открыть карту или инвентарь из просмотра и вернуться: старый снимок не восстанавливается.
5. Переместить панель штатным редактором HUD и изменить её масштаб; повторить просмотр, включая край экрана.
6. Убедиться, что эффекты персонажа, KanaBuffPanels и обычные подсказки работают как прежде.

Локальные Lua-тесты не подтверждают отрисовку, hit testing, реальные координаты при масштабировании и работу в клиенте ESO. Совместимость с заменой штатной панели LUI/Srendarr не заявляется. Gamepad preferred mode не включает просмотр мышью.
