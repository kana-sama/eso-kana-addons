# KanaOutfitBrowser

Версия 0.2.0 добавляет категорию **Сеты** в штатный раздел **Коллекции → Стили нарядов → Стили доспехов**, после категорий частей брони. Отдельная вкладка аддона и эксперимент с поясом больше не загружаются.

После обновления выполни `/reloadui`, открой «Стили нарядов» и выбери «Сеты».

Для каждого сета показаны название, глаз и звезда. Ниже — отдельная строка из семи штатных кнопок на каждый имеющийся вариант: голова, грудь, плечи, перчатки, пояс, ноги, обувь. Варианты идут от лёгкого к тяжёлому; отсутствующие части оставляют пустую ячейку. Предметы примеряются обычным двойным щелчком по штатной кнопке. Автоматической примерки всей строки нет.

- Незачёркнутый глаз означает видимый сет, зачёркнутый — скрытый.
- Контурная звезда означает обычный сет, заполненная — любимый.
- Обе отметки относятся ко всему сету со всеми его вариантами.
- После нажатия значок и цвет названия меняются сразу. Список не прыгает: скрытие и поднятие любимых применяются при следующем входе в «Сеты» (после другой категории или повторного открытия окна).
- «Показать скрытые» позволяет найти и вернуть скрытые сеты.
- Штатный поиск фильтрует по названию сета. Штатная галочка показа заблокированных управляет видимостью недоступных предметов.

Настройки сохраняются на аккаунт и игровой мир в `KanaOutfitBrowserSavedVariables.nativeSets`. Старые настройки отдельных вариантов сохранены, но новый режим их не использует.

Если ESO возвращает нулевой ID стиля, каталог использует резервную группировку по пути иконки `gear_<стиль>_<вес>_<часть>_<вариант>`. Это эвристика: варианты внешнего вида сохраняются отдельными строками. Нераспознанные пути показываются отдельными предметами, без предположений об их принадлежности к сету. Новый режим рассчитан на клавиатурный интерфейс ESO.

## Реализация и проверка

Аддон добавляет данные в штатную сетку через `SecurePostHook` после очистки пула записей, как в подтверждённом в игре эксперименте с поясом. Шаблон кнопки и обработчики примерки остаются штатными. Приватные функции примерки аддон не вызывает.

Проверки `tests/test_catalog.lua`, `tests/test_native_set_model.lua` и `tests/test_native_sets.lua` покрывают каталог, отложенную сортировку/скрытие и вставку нативных данных. Окончательное отображение и работу новой категории нужно проверить в клиенте игры. История прежних неудачных подходов: [docs/api-evidence.md](docs/api-evidence.md). Старые модули и их тесты оставлены как история экспериментов; в манифесте подключены только четыре файла нового режима.

Нажатие на название сворачивает или разворачивает стиль; состояние сохраняется. При переключении фильтров прокрутка привязана к верхней видимой строке сета. Если строка исчезла, выбирается ближайшая оставшаяся. Порядок стилей фиксируется при первом открытии после обновления; новые стили добавляются в конец. Избранные по-прежнему поднимаются при следующем входе.

## Проверка полного каталога (0.2.2)

Группировка проверена на сохранённых 4980 записях реального клиента: 397 групп, 960 вариантов, ни один ID не потерян. Поддержаны сокращённые и отсутствующие обозначения веса, версии имён иконок и подтверждённые опечатки. Место предмета определяется API допустимых слотов даже при ошибке в имени иконки. Неустрашимые разделены по конкретным наборам; опаловые варианты не смешиваются с обычными. Альтернативы всех слотов сохраняются отдельными строками.

`tests/fixtures/catalog-client.json` содержит только игровые поля коллекционных предметов, без имени аккаунта. `tests/test_client_catalog.py` воспроизводит весь каталог в Lua 5.1 (через lupa), проверяет сохранность ID, допустимые слоты, проблемные группы, независимость от порядка входа и перенос настроек. `docs/catalog-audit.txt` перечисляет оставшиеся небольшие группы для проверки: маленькая группа сама по себе не означает ошибку (например, маска/наплечник или одиночный косметический предмет).

При первом входе после обновления ключи избранного, скрытия, сворачивания и сохранённого порядка переносятся на новые группы. Скрытие одной старой отдельной части не скрывает целиком объединённый стиль.
