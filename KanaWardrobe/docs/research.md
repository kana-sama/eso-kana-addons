# KanaWardrobe — разбор Wizard’s Wardrobe перед реализацией

Дата проверки: 2026-09-28. Это исследование исходного кода, не отчёт о воспроизведении в ESO.

Изучена установленная версия **WizardsWardrobe 1.23.2**, manifest API **101048**. Версия совпадает с [публикацией автора](https://www.esoui.com/downloads/info3170-WizardsWardrobe.html). Просмотрены сохранение/загрузка, перемещения, валидация, восстановление, очередь, банки, маркеры, предпросмотр и импорт. Дополнительно проверены опубликованные исходники ESO и публичные интерфейсы LibFilters. Фактическую версию работающего клиента предстоит получить через `GetAPIVersion()`; номер из manifest WW не задаёт совместимость нового аддона.

## Места, которые особенно опасно копировать буквально

В `MoveItems` [проверка с комментарием про пять секунд](</Users/kana/Documents/Elder Scrolls Online/live/AddOns/WizardsWardrobe/WizardsWardrobe.lua:468>) сравнивает `GetTimeStamp()` с `timeStamp + 5000`. API возвращает секунды. Это несоответствие единиц в изученном коде, **не воспроизведённый нами баг клиента**. Для нового движка использовать время в миллисекундах и тест с управляемыми часами.

В записи перемещения [создаётся поле `delay`](</Users/kana/Documents/Elder Scrolls Online/live/AddOns/WizardsWardrobe/WizardsWardrobe.lua:613>), но изученный основной цикл его не читает. Объявленный [itemTaskQueue](</Users/kana/Documents/Elder Scrolls Online/live/AddOns/WizardsWardrobe/WizardsWardrobe.lua:427>) имеет извлечение, но поиск по установленному коду не нашёл добавления в эту таблицу. Нельзя считать наличие этих имён доказательством работающей задержки или надёжной сериализации.

Таймаут нашего ожидания также **не отменяет уже отправленный игровой запрос**. Поздний результат может изменить экипировку после остановки Lua-цепочки. Поэтому нужен журнал незавершённого запроса и повторная сверка перед восстановлением, а не немедленный повтор той же команды. Метки операций защищают callbacks, но сами по себе не отменяют серверные действия.

## Что WW не решает за нас

**Подсчёт сетов в ещё не надетом пресете.** Штатный [`ZO_Tooltip:AddSet`](https://github.com/esoui/esoui/blob/live/esoui/publicallingames/tooltip/itemtooltips.lua) берёт текущие `numNormalEquipped`/`numPerfectedEquipped` и ограничивает сумму `maxEquipped`. Нужно отдельно считать состав пресета, обе панели, вес двуручного оружия, семейство совершенных вещей и пороги дополнительных бонусов. Наш текст может показывать 6/5. Замена только метода `AddSet` собственного экземпляра должна сохранить его возвращаемые значения о подавлении бонусов и вывод ограничений сета. Полный tooltip-layout и размеры требуют ранней проверки в игре.

**Точное скрытие в разных окнах.** [`backpacklayouts.lua`](https://github.com/esoui/esoui/blob/live/esoui/ingame/inventory/backpacklayouts.lua) меняет фильтры при переходе в банк/магазин. Продажа NPC и помещение в гильдейский банк сами исключают заблокированные вещи. Выключение нашего фильтра не отменяет эти правила. [`repairwindow.lua`](https://github.com/esoui/esoui/blob/live/esoui/ingame/repair/repairwindow.lua) собирает отдельный список из BAG_WORN и BAG_BACKPACK — одного перехвата обычной сумки недостаточно. «Починить всё» сохраняет штатную семантику.

Если установлен LibFilters, использовать [публичный API](https://github.com/Baertram/LibFilters-3.0/blob/master/API.lua): `RegisterFilter(tag, filterType, callback, noInUseError)`, `UnregisterFilter(tag, filterType)`, `RequestUpdate(filterType, delay)`. Регистрация сама не обновляет окно. Для различных списков существуют [отдельные LF_* константы](https://github.com/Baertram/LibFilters-3.0/blob/master/files/constants.lua), включая ремонт, домашний банк и гильдейскую продажу. В исследованной установке библиотеки нет; во время исследования она не устанавливалась.

**Обычный тултип и действие разблокировки.** [`inventoryslot.lua`](https://github.com/esoui/esoui/blob/live/esoui/ingame/inventory/inventoryslot.lua) даёт контекст bag/slot для `SetBagItem`/`SetWornItem`. Каталог магазина и произвольная ссылка такого контекста не гарантируют. В [`inventoryslotactions.lua`](https://github.com/esoui/esoui/blob/live/esoui/ingame/inventory/inventoryslotactions.lua) `AddSlotAction` сразу добавляет пункт контекстного меню: менять готовую таблицу действий после этого слишком поздно. Первоначальная рекомендация заменить только callback разблокировки оказалась небезопасной: обёртка общей функции discovery выполняет создание остальных callbacks из недоверенного кода и нарушает защищённый вызов UseItem (ошибка клиента 2026-09-28). Не подменять discovery, AddSlotAction и callbacks штатных действий. Использовать блокировку по событиям инвентаря; не переопределять SetItemIsPlayerLocked.

**Сохранение незаконченного редактора.** Запись Lua-таблицы SavedVariables ещё не означает запись на диск. [FAQ автора WW](https://github.com/nicokimmel/wizardswardrobe/wiki/FAQ) описывает сохранение при штатном выходе или reload. Журнал помогает после `/reloadui` и нормального выхода, но не даёт гарантии после аварийного завершения процесса. Отмена редактора также не может отменить игровую привязку вручную надетой новой вещи.

## Три ранних клиентских проверки

1. Два собственных полных тултипа одновременно: искусственные 3/5 и 5/5, обе панели, совершенный бонус, неизменённый обычный ItemTooltip.
2. Операции с настоящими UID: заблокированная вещь, обмен при полной сумке, кольца, перенос оружия в обе стороны, двуручное + щит, мифик между слотами, Oakensoul/недоступная запасная панель. Результат определяет подтверждённые возможности адаптера; неподтверждённую оптимизацию обмена не включать.
3. Панель и 14 галочек рядом с KanaCurrentlyEquipped/KanaInfoBar: русский текст, реальные масштабы UI, несколько карточек, возврат исходных привязок после повторного входа.

Эти проверки включены в [план реализации](</Users/kana/Documents/Elder Scrolls Online/live/AddOns/docs/superpowers/plans/2026-09-28-kana-wardrobe.md>). До их выполнения архитектура определена, но совместимость с конкретным клиентом и визуальное качество не считаются подтверждёнными.
