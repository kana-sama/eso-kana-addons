# KanaLeadList

Надстройка для LeadList 50.1.1. Включать вместе с LeadList; исходные файлы,
база зацепок и настройки LeadList не заменяются.

- **Можно выкопать впервые** в первом списке: зацепка есть и `Dug == 0`.
  Это пересечение штатных «Можно выкопать» и «Ни разу не выкопанные».
- **Скрыть обычные и простую мебель** в списке типов: правила штатного
  «Скрыть обычные» для сокровищ и мотивов плюс скрытие декоративной мебели
  любой редкости. При выборе «Можно выкопать» или «Можно выкопать впервые»
  сохраняется особое штатное правило: из сокровищ скрываются только начальные.
- Для составной древности классифицируется конечная награда набора.
  Используются игровые API предметов/коллекций, категория мебели Services (25)
  и специализированные типы станков/манекенов. В частности, мастерская
  вооружения Гильдии воров и её части остаются видимыми.
- Функциональность означает практическую пользу. Свет, музыка, возможность
  сесть или переключить декоративный эффект сами по себе не считаются услугой.
  Награды с отсутствующими/неизвестными метаданными остаются видимыми.
- При сортировке по зоне используется сравнение нормализованного UTF-8 текста
  по байтам, затем названия древности и ID. Это устраняет зависимость от
  `strcoll` macOS, где русская локаль может считать разные названия равными
  по порядку. Другие столбцы сохраняют штатную сортировку.
- При наведении на строку рядом с исходным тултипом зацепки появляется штатный
  тултип конечной награды: готового предмета/коллекционного предмета за весь
  набор, либо награды за одиночную древность. Используется отдельный контрол;
  тултип очищается при уходе мыши или закрытии LeadList.
- Двойной щелчок левой кнопкой по строке запускает лоцирование этой древности
  через штатный `ScryForAntiquity`. Перед запуском `CanScryForAntiquity`
  проверяет текущие игровые условия. При отказе показывается игровая причина,
  а список остаётся открытым; при разрешении окно LeadList закрывается.
- ПКМ по заголовкам таблицы открывает меню с флажками всех семи колонок.
  Выбор сохраняется; скрытые колонки не оставляют промежутков. Последнюю
  видимую колонку скрыть нельзя. При скрытии текущей колонки сортировки
  сортировка переключается на первую видимую. ЛКМ по заголовкам работает
  как в исходном LeadList.
- Видимые колонки заполняют доступную ширину таблицы. Свободное место сначала
  получают колонки с обрезанными заголовками/значениями, затем текстовые колонки.
  Размеры рассчитываются по игровым шрифтам и всем строкам текущего фильтра,
  пересчитываются при изменении фильтра и набора видимых колонок.
- Строки текущей зоны персонажа выделены голубым фоном; цвета редкости и
  таймера сохраняются. Выделение следует зоне, указанной LeadList в строке
  (для имеющейся зацепки — зоне раскопок, для отсутствующей — зоне получения),
  обновляется при переходах и не зависит от просмотра другой зоны на карте.

Выбор двух новых пунктов сохраняется в `KanaLeadListSavedVariables`, чтобы
штатная проверка известных пунктов при загрузке не сбрасывала его. Обновления
LeadList не перезаписывают эту папку; изменения его API могут потребовать
обновления надстройки.

## Проверки

Из папки AddOns, с Lua и копией исходников интерфейса ESO:

```sh
ESOUI_PATH=/tmp/esoui-live lua KanaLeadList/tests/test_leadlist.lua
ESOUI_PATH=/tmp/esoui-live lua KanaLeadList/tests/test_leadlist.lua restore
ESOUI_PATH=/tmp/esoui-live lua KanaLeadList/tests/test_leadlist.lua deferred
```

Тесты исполняют установленные методы фильтрации LeadList и штатный
`ZO_TableOrderingFunction`. Проверка ошибки локали требует macOS с
`ru_RU.UTF-8`. Ответы API наград в тестах синтетические; это проверка ветвей
классификации, а не подтверждение текущего игрового каталога.

В игре: включить оба аддона, открыть `/leads`, проверить совместное применение
двух новых фильтров, мастерскую и её части, группировку Даашана в обоих
направлениях, затем `/reloadui` и сохранение выбора. Живой интерфейс игры
автоматическими Lua-тестами не проверяется.
