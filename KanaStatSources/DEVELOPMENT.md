# KanaStatSources

Таблица источников в штатных тултипах 15 основных характеристик персонажа: максимальные ресурсы, восстановление, сила оружия/заклинаний, критический шанс, пробивание и сопротивления. Интерфейс клавиатуры и мыши, ESO API 101051, без зависимостей.

Включите **KanaStatSources** в списке аддонов и выполните `/reloadui`. Наведите курсор на характеристику в окне персонажа. Две колонки показывают короткое название с маленькой иконкой и числовой эффект. Названия жёлтые, значения белые, весь текст жирным штатным шрифтом характеристик; заголовков колонок нет. Иконки CP соответствуют цветным веткам. Базовое значение и атрибуты тоже имеют иконки; иконки атрибутов такие же, как в инфо-панели KanaWardrobe. Для критического шанса все значения показаны в процентах, внизу — только **«Итого»** и текущий процент.

Ширина равна месту для самой длинной строки: иконка, название, отступ и значение; минимум — штатные 350 единиц интерфейса, максимум — граница экрана. Названия занимают одну строку. Описание переносится внутри этой же ширины. При неизменных строках обновления сохраняют размер; появление более длинного источника сразу пересчитывает ширину. Если строки не помещаются, оставьте курсор на характеристике и вращайте колесо мыши; итог закреплён внизу.

Сумма числовых вкладов равна текущему значению API; проценты крита в строках округляются для отображения. Округление распределяется между дробными вкладами после округления общей суммы, поэтому отдельные процентные строки не создают лишнюю единицу. Подписанный остаток **«Неизвестно»** сохраняет реальные расхождения и может быть отрицательным. Нулевые строки скрыты, исходные данные остаются в дампе. Черновые атрибуты показываются отдельным предпросмотром. При нестабильном снимке объяснённые источники исключаются, чтобы не смешивать разные состояния персонажа.

Тултип статов использует отдельный штатный контрол ESO. Содержимое сохраняется до завершения анимации исчезновения. Общий тултип карты и других окон не изменяется.

Для процентных модификаторов показаны числовой вклад и процент в скобках. Слот предмета, ранг навыка, сохранённые очки CP и база умножения остаются в диагностическом дампе. Одинаковые предметы в разных слотах имеют отдельные строки с собственными вкладами.

Расчёт общий для всех характеристик и обновляется при изменениях персонажа. Снаряжение и неизменные описания кешируются; повторное наведение не собирает весь build заново. Обновления не сбрасывают позицию прокрутки.

Распознаются: базовый критический рейтинг из API без бонусов; база ресурсов/силы, восстановления 309/514/514 и сопротивления криту 1320 для уровня 50 CP160+ без battle leveling; потраченные атрибуты с процентными модификаторами; броня, сила основной руки, постоянные зачарования и поддержанные свойства; постоянные пороги сетов; безусловные изученные пассивки активных линий, включая «Эрудицию»; «Щит и меч» при одноручном оружии и щите на активной обычной панели; текущие бонусы действующих CP; еда/напитки; native-вклады Мундуса; простые действующие бафы и дебафы. Числа в RU/EN описаниях берутся из текущего клиента.

Версия 1.0.6 берёт базу крита из `GetPlayerStat(..., STAT_BONUS_OPTION_DONT_APPLY_BONUS)`. Снимок без экипировки и CP на крит подтвердил 2181 рейтинга, то есть 9,953449%, округляемые штатным UI до 10,0%. Прежнее преобразование ровно 10% в рейтинг завышало базу и создавало ложные −0,05%. Для других характеристик этот API-параметр не используется как доказательство чистой базы; недоступная база крита остаётся неизвестной.

В версии 1.0.7 все проценты критических источников и итог используют тот же `zo_strformat(SI_STAT_VALUE_PERCENT, chance)`, что и штатное окно персонажа. База и итог на снимке без бонусов оба показывают 10,0%; разная точность 9,95%/10,0% больше не используется. Точные рейтинги и проценты сохраняются в дампе.

Версия 1.0.10 использует общее правило «Точности» для предметов: процент берётся из текущего native описания свойства и переводится в рейтинг через калибровку `GetCriticalStrikeChance`. Вклад каждого предмета округляется вниз до целого рейтинга перед суммированием. Название, ID, сет, тип оружия, качество, уровень предмета и CP не выбирают фиксированное число из таблицы. Одно- и двуручное оружие используют уже указанный в описании процент; дополнительно удваивать его не нужно. При недоступной или нелинейной native конверсии вклад остаётся неизвестным.

В версии 1.0.13 постоянные сетовые бонусы силы оружия/заклинаний используют принятую пользователем рабочую гипотезу: значения из описаний отдельных предметов (`equipped=false`) усредняются по активным частям сета, двуручное оружие имеет вес 2, остальные вещи — 1. Среднее округляется вниз до применения процентных бафов. Правило использует текущие значения любых предметов, а не таблицу для конкретного сета, качества или уровня. Для других характеристик сохранено описание активного сета. При недостаточных данных сохраняются прежний расчёт и диагностическая причина, без частичного среднего.

Дамп #6 подтверждает **2181 + 1358 = 3539** с посохом, а #7 — **2181 + 679 + 679 + 160 CP = 3699** с двумя кинжалами. В последнем случае видны две отдельные строки предметов по **3,1%**, «Точность» CP **0,7%**, итого **16,9%**. Правило версии 1.0.9, распознававшее только фиолетовый грозовой посох CP160, удалено.

Маленькие настоящие ненулевые критические вклады сохраняют дополнительные знаки. Исправлена ошибка локализации версии 1.0.8: штатный форматтер получает число с английской десятичной точкой, затем сам применяет локаль. Проценты источников считаются из сырых вкладов рейтинга; итог сохраняет штатный формат. Неизвестные остатки остаются в расчёте и дампе.

Версия 1.0.11 учитывает базовую силу оружия во второй руке: `floor(сила предмета × 0,178)` входит в общую сумму до процентных бонусов. Правило использует текущую силу любого одноручного оружия и проверяет обе руки на активной обычной панели. Дампы #9 и #10 полностью объясняют силу 3128 → 3181: 2% «Ловкости» прибавляются к 20% «Великой жестокости» на общей базе 2607. Остатки 241 и 246 исчезли; дополнительный неизвестный бонус остаётся неизвестным.

Условные бонусы за число предметов/навыков, оружейные специализации, некоторые CP-форматы, особые сетовые proc, проклятия и окружение могут остаться неизвестными. Неизвестные проценты не умножают итог автоматически. На другом языке остаются подписи EN, native-вклады и остаток; текстовые правила RU/EN не применяются. Окно дополнительных характеристик и gamepad-тултипы не расширяются.

## Диагностический снимок

Введите **`/kanastats dump`**. Команда работает и до открытия окна персонажа. Она сохраняет последние десять снимков с последовательными ID в `KanaStatSourcesSaved.dumps`. После `/reloadui` или выхода из игры данные появятся в:

`Documents/Elder Scrolls Online/live/SavedVariables/KanaStatSources.lua`

В снимок входят все основные и дополнительные значения API, обе панели, изученные пассивки активных и неактивных линий, сохранённые CP и слоты, надетые предметы и их native metadata, сетовые пороги, все текущие эффекты и их полные описания, Мундус, контекст уровня/проклятия/battle leveling, критические пробы, вклад каждого источника, видимый и сырой остатки, кандидаты, ошибки API и статусы доступности категорий. Файл предназначен для анализа на компьютере; аддон не отправляет данные по сети.

Для поиска недостающего источника сравните два дампа до и после одного изменения: например, снятия предмета, окончания еды, смены CP или панели. Смотрите `snapshot`, `contributions`, `breakdowns[stat].rawUnknown`, `diagnostics` и `snapshot.errors`. Кандидат не считается подтверждённым числовым вкладом.

В версии 1.0.12 полный дамп также сохраняет `snapshot.equipmentAudit` и `snapshot.setAudit`: значение предмета из `GetItemStatValue(BAG_WORN, slot)`, свежее чтение силы по ссылке, описания бонусов сета по каждому предмету с `equipped=true/false` и отдельно через `GetItemSetBonusInfo`. Эти независимые чтения нужны для сравнения API; они не заменяют вклад в расчёте и не выполняются при наведении на стат. Недоступные функции отмечаются в `snapshot.errors`.

Начиная с 1.0.13 `snapshot.equipment[].setBonuses` сохраняет индивидуальные значения, используемые в расчёте силы; они читаются вместе с экипировкой и кэшируются. `contributions[].source.damageAverages` сохраняет исходное описание надетого сета, сумму с весами, число частей, среднее, итог после округления и значения каждого участвующего предмета. Правило отмечено как рабочая гипотеза, принятая пользователем, чтобы следующий дамп позволил проверить его без восстановления входных данных по остаткам.

Правила и ограничения описаны в [docs/research.md](docs/research.md). Автоматические проверки: `lua KanaStatSources/tests/run.lua` из корня репозитория. Проверка в игре: [docs/client-validation.md](docs/client-validation.md).
