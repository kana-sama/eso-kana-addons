# Проверка реализации

2026-10-06. Итоговый набор: **93 tests passed, 0 failed** в Lua 5.4 и Lua 5.1. Синтаксис всех Lua-файлов дополнительно проверен через Lua 5.1. Регрессии соседнего KanaTTC: **186 checks passed**. `git diff --check` прошёл. Файлы manifest существуют; тесты в manifest не подключены.

Независимое ревью выявило три важных ошибки. Каждая воспроизведена падающим тестом и исправлена:

- `passive_effect_identity`: одинаковый ability ID у пассивки и активного эффекта учитывается один раз для соответствующего стата; независимые ID сохраняются.
- `malformed_results`, `collector_isolation`, `nullable_api`: NaN/Infinity, неверные и отсутствующие количества не запускают небезопасный обход; сбой коллектора не уничтожает остальные категории. Допустимый nil у native полей не становится ошибкой.
- `very_small_body`: даже при большом native описании остаётся положительная область прокрутки; footer и последний источник достижимы.

Замечания к отображению базы процента и различению одноимённых предметов были признаны важными для проверяемости источников. Тесты `percentage_base_visible` и `same_named_slots_visible` воспроизвели проблему до исправления. Теперь показаны база умножения, слот предмета, ранг навыка и потраченные CP. Дополнительно исправлены Triune, Impenetrable с отдельным бонусом прочности и попытка применить RU/EN числовые правила к другому языку.

Десять текущих русских описаний зачарований из локального сохранённого preview KanaWardrobe распознаны без остаточного текста. Эти данные проверяют текстовый разбор, а не фактическое состояние персонажа в игре.

## Принятые решения

1. Работа выполнена в установленном checkout под AddOns: пользователь явно потребовал продолжить без согласований skill. Изменения ограничены новым аддоном и документацией, сохранены локальными коммитами. Цена ошибки при выборе среды: понадобится отдельная проверка установленного клиента; история кода сохранена.
2. Синтетические фикстуры отдельных провайдеров размещены рядом с тестами, общая — в `tests/fixtures/complete_build.lua`. Это исключает повторение одного формата снимка в нескольких вспомогательных файлах. Цена ошибки: фикстуры понадобится разделить при усложнении тестов.
3. Условные взаимодействия без проверенного ID-правила и масштабирования остаются кандидатами и signed остатком. Базовая константа ограничена контекстом, уже эффективные native-вклады не умножаются повторно. Цена решения: остаток может быть большим, пока дамп из игры не позволит расширить правила.
4. Замечания к процентной базе и видимому слоту/рангу повышены из minor до important: без них пользователь не может воспроизвести расчёт или отличить одноимённые источники. Цена решения: больше текста в строках; ограничение высоты и прокрутка проверены.

Внешний вид, фактическая загрузка новым клиентом и запись SavedVariables после `/reloadui` **ещё не проверены в ESO**. Выполнить [client-validation.md](client-validation.md). Последующее независимое ревью после исправлений не запускалось; исправления подтверждены воспроизведением ошибок и всем набором тестов.

## Ошибка запуска из клиента

Пользователь воспроизвёл падение на `Table.lua:16`: вызов несуществующего `SetMouseWheelEnabled`. Удалён этот метод из тестовой заглушки, после чего все пять tooltip-тестов воспроизвели ошибку. Удалены оба вызова из production-кода. Прокрутка использует native `SetMouseEnabled` и `OnMouseWheel`; новая регрессия проверяет колесо на строке характеристики и теле таблицы, сохранение исходного обработчика и прекращение прокрутки после ухода курсора. Остальные методы Table/Tooltip сверены с API 101051 — других отсутствующих вызовов не найдено. Повторный запуск в ESO после этого исправления ещё не подтверждён.

## Приватные функции при сборе снимка

На следующем наведении клиент сообщил об обращении к приватной `PickupStoreItem` на `Snapshot.lua:39`. Причина — `pairs(_G)` получал значения всех глобальных полей до фильтрации имени/типа. Аналогичный обход был при сборе capabilities. Оба обхода удалены: константы читаются по известным именам enum API 101051, capabilities записываются безопасным reader только для публичных методов, используемых коллекторами. Имена API кешированного build сохраняются отдельно в обычной таблице аддона.

`private_globals_are_not_enumerated` запрещает обход таблицы API и проверяет обычный снимок, полный дамп, сохранение констант и доступность используемых/отсутствующих методов. Тест воспроизвёл исходную ошибку до изменения и проходит после него в Lua 5.1 и 5.4. Исправление ещё требует повторного `/reloadui` в клиенте.

## Дамп из клиента: пропавшие источники и задержки

Прочитан сохранённый снимок #1 от 2026-10-06 (API 101051). В нём есть все надетые предметы, семь постоянных зачарований на запас сил, сетовые бонусы, еда «Лавовая нога», изученные пассивки и действующие CP. Сбой числовой атрибуции произошёл после сбора данных.

- RU-формат еды с `ед., а … — на … на … ч.` и текст CP «Увеличение … на …» не поддерживались. Добавлены эти формы и расовые пассивки с обратным порядком слов. Нераспознанный нормализованный остаток теперь сохраняется в diagnostics.
- Старый разбор зачарований воспроизводится на тех же текстах вне ESO, но не сработал в клиенте. Нормализация регистра переведена на штатный `LocaleAwareToLower`, как в [globalapi.lua](https://github.com/esoui/esoui/blob/live/esoui/libraries/globals/globalapi.lua); byte-safe fallback остаётся для обычного Lua. Точная причина несовпадения старого нормализатора с клиентом вне игры не воспроизведена.
- Постоянные эффекты из этого дампа имеют `startTime == endTime`, а не обязательно `endTime == 0`. Они больше не отбрасываются как истёкшие. Добавлено чтение `IsAbilityPermanent` и native описания активного эффекта через `GetAbilityEffectDescription(buffSlot)`. Пустой текст `GetAbilityDescription` не считается доказательством отсутствия бонуса.
- Для известных ID пассивок используется native «Текущий бонус», уже учитывающий панель и броню. Эти тексты обновляются отдельно от кеша build. Оружейные пассивки требуют отдельного правила активного оружия: изученный «Щит и меч» не даёт бонуса с посохом.
- Автопроверка формулы критического шанса отклоняла пробы API из-за float32-погрешности около 0,000002 процента. Допуск учитывает два относительных float32 epsilon; нелинейная формула по-прежнему отклоняется. Пробы дают `6864 / 219,12 = 31,3%`.
- Повторные наведения используют общий расчёт. Снаряжение кешируется до смены экипировки; проверка стабильности повторно читает только значения и идентификаторы, а не длинные описания. Парсер имеет ограниченный кеш неизменных текстов. Первый расчёт подготавливается после загрузки, события объединяются в одно обновление.
- Шрифт таблицы увеличен. Подсказка о колесе появляется при переполнении; обновление тултипа сохраняет прокрутку. Числовой слот колец не дублирует native имя «Кольцо 1».

Санитизированная фикстура `tests/fixtures/live_ru.lua` содержит реальные тексты и числа, без имени/ID персонажа и аккаунта. На повторном расчёте дампа макс. здоровье, макс. магия, оба пробивания и оба сопротивления сходятся полностью. Для запаса сил показаны 13 строк, включая еду, семь зачарований, расовую пассивку и CP; подписанный остаток — 421. Этот остаток не распределяется по источникам догадкой. В исходном снимке нет описаний активных эффектов по buffSlot: для дальнейшей атрибуции нужен новый дамп версии 1.0.1.

Новые тесты воспроизвели пропуск еды/CP/пассивок, слишком строгую проверку критических проб, повторные сборы, устаревший «Текущий бонус», ложный бонус оружейной пассивки, лишнюю подсказку и сброс прокрутки до исправлений. Проверено **93 tests passed, 0 failed** в Lua 5.4 и Lua 5.1; **186** соседних TTC-проверок также проходят. Новый код и оформление после этих исправлений ещё не проверены в работающем клиенте ESO.
