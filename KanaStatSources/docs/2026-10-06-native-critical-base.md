# Причина остатка −0,05% критического шанса

Контрольный dump #4: API 101051, addon 1.0.5, уровень 50 CP527, consistent=true. Надетых предметов нет, вкладов CP на крит нет, активен камень Любовника (пробивание).

| Значение | Крит оружия | Крит заклинаний |
| --- | ---: | ---: |
| Native итоговый рейтинг | 2181 | 2181 |
| Native рейтинг без бонусов | 2181 | 2181 |
| Native шанс для этого рейтинга | 9,9534492493% | 9,9534492493% |
| Прежняя база из ровно 10% | 2191,2000613031 | 2191,2000613031 |
| Прежний сырой остаток | −10,2000613031 | −10,2000613031 |

Прежний источник завышал базовый рейтинг: номинальные 10% из старых описаний не равны точному текущему шансу API. После округления остаток −10 рейтинга отображался как −0,05%. Это ошибка атрибуции базы в аддоне; внутреннее происхождение числа 2181 в движке не установлено.

Версия 1.0.6 использует отдельно захваченный `GetPlayerStat(criticalStat, STAT_BONUS_OPTION_DONT_APPLY_BONUS)` без восстановления рейтинга из процента. Источник ограничен API 101051, принимает конечное неотрицательное целое значение. При отсутствии данных остаются диагностика и неизвестный остаток. Правило применяется только к двум критическим характеристикам: для ресурсов/восстановления этот параметр может возвращать итог с бонусами.

Независимая проверка на неизменённых экипированных dumps #2/#3: **2181 + 1701 камня Вора + 160 CP = 4042**, совпадает с native итогом обоих критов. Dump #4: **2181 = 2181**, остатка нет. В версии 1.0.6 в dump #1 ещё оставались отдельные неизвестные −1 рейтинга; их причина установлена ниже.

## Ошибка «Точности», установленная дампом #6

Контрольный dump #6, consistent=true, содержит один фиолетовый грозовой посох CP160 со свойством «Точность». Оба критических рейтинга равны 3539. Относительно голого персонажа #4 предмет добавляет ровно **3539 − 2181 = 1358**.

Раньше округлённые «6,2%» из описания обратно пересчитывались в 1358,544 очка. Общая сумма округлялась до 3540, поэтому аддон выдумывал отрицательный остаток −1. Это ошибка источника, а не отрицательный бонус персонажа. Из одного наблюдения нельзя заключать, что все свойства и процентные источники округляются вниз.

Версия 1.0.9 использует подтверждённые 1358 для проверенных metadata предмета и контекста. Непроверенные варианты «Точности» сохраняются в диагностике. Повторный расчёт #6 даёт **2181 + 1358 = 3539**, а полного комплекта #1 — **2181 + 1358 + 634 + 634 + 1897 + 160 = 6864**, оба без остатка. Пересчитаны все шесть исходных дампов: у обоих критов integer/raw unknown равны нулю.

Предыдущая попытка изменить точность отображения также передавала заранее локализованное −0,002 в штатный форматтер, что нарушает его [требование английских разделителей](https://github.com/esoui/esoui/blob/live/esoui/libraries/globals/localization.lua#L129). Исправлено отдельно: локализацию выполняет штатный форматтер. Его реальная грамматика и экранный результат требуют проверки в ESO после `/reloadui`.

## Общее правило свойства, версия 1.0.10

В dump #7 вместо посоха надеты два одинаковых кинжала с «Точностью» по 3,1%; отдельно CP добавляет 160 рейтинга. Итог 3699: **3699 − 2181 − 160 = 1358**, то есть 679 с каждого кинжала. Они оставались неизвестными из-за ограничения правила версии 1.0.9 по типу оружия, а не из-за применения CP.

Ограничение удалено. Процент каждого предмета переводится через текущую калибровку API и округляется вниз до целого перед суммированием. Это общий расчёт свойства, без списка конкретных предметов, качества или CP160. Для имеющихся данных **floor(6,2 × 219,12) = 1358** и **floor(3,1 × 219,12) = 679**. Коэффициент 219,12 здесь приведён для объяснения дампов; в коде он не зафиксирован. Процент уже содержит масштаб оружия, поэтому повторного удвоения нет.

Повторный расчёт всех семи исходных дампов совпадает с native итогами обоих критов без integer/raw неизвестного остатка. Структурные тесты других metadata, процентов и коэффициентов проверяют общий механизм; фактические значения всех других сочетаний в клиенте этими тестами не подтверждены.
