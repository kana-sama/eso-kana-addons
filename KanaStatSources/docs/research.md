# Sources and limits (API 101051)

Native source: [ESO UI repository](https://github.com/esoui/esoui), API documentation `ESOUIDocumentation.txt` (101051), and `esoui/ingame/stats/keyboard/zo_statentry_keyboard.lua`.

`GetPlayerStat(stat, STAT_BONUS_OPTION_APPLY_BONUS)` is the authoritative rating/integer. `DONT_APPLY_BONUS` is captured for investigation, but does not prove a pure base value. Never infer a base from the unexplained remainder.

[ZOS Update 29 notes](https://forums.elderscrollsonline.com/en/discussion/564242/pc-mac-patch-notes-v6-3-5-flames-of-ambition-dlc-update-29) establish base health 16000, magicka/stamina 12000, weapon/spell damage 1000. This rule is limited to API 101051, level 50, CP160+, and explicitly absent battle leveling. Other contexts retain the residual. In that same supported context, verified recovery bases are health 309, magicka/stamina 514, and critical resistance 1320. These follow [UESP author formulas after Update 29](https://github.com/uesp/uesp-esochardata/blob/0e58d0871bd63b994d56c6572d400e500b2e326a/editBuild.class.php#L2328), unchanged in the [Update 32 formulas](https://github.com/uesp/uesp-esochardata/blob/bbe4939b259acfcf9b7dd05e14f7da4ba7c4a8d9/editBuild.class.php#L2437), and independently reproduce the three API 101051 recovery totals in dump #3. Other levels are not extrapolated from these historical formulas. [ZOS Update 26](https://forums.elderscrollsonline.com/en/discussion/528633/pc-mac-patch-notes-v6-0-5-greymoor-update-26/p1) introduced base critical resistance at level 10; this addon only assigns its numeric rating in the supported level-50 context.

[ZOS v1.6.5 notes](https://forums.elderscrollsonline.com/en/discussion/154426/patch-notes-v1-6-5) establish base Critical Hit chance 10%. For API 101051 this is a separate `criticalChance` contribution converted with the running client's calibration, independent of the resource/damage level restrictions. It is not added a second time to the native total, and `DONT_APPLY_BONUS` is not treated as proof of its numeric rating. Unavailable calibration leaves a diagnostic and the unknown residual.

`GetAttributeDerivedStatPerPointValue(attribute, stat)` supplies the native current delta used by `ZO_AttributeSpinner_Shared` for pending stat bonuses. Committed points use this raw delta with operation `flat`, so resource percentages include attributes. The latest native health per-point delta is 122 despite an active 5% Juggernaut: it is not pre-multiplied. UESP resource formulas likewise add attributes before applying resource percentages. Pending points are separate from current totals.

`GetItemLinkArmorRating(link, true)` includes condition and local traits; `GetItemLinkWeaponPower(link)` is the item's power. Main-hand power is attributed directly; the offhand's effective scaling is a candidate pending evidence. Item-specific enchant descriptions are already adjusted for Infused. Charged glyphs require an active effect. Trait IDs determine the trait's meaning; unrecognized traits do not contribute guessed values.

`GetItemLinkSetInfo(link, true)` returns normal and perfected active equipped counts. Normal thresholds use their sum; perfected thresholds use only perfected count. `GetItemSetUnperfectedSetId` identifies the family. Family, threshold, perfected flag and description deduplicate shared bonuses across links. Conditional proc descriptions remain candidates even at the required item count.

Descriptions support complete RU/EN stat clauses. The parser stops at a conditional/unknown tail, retaining recognized permanent prefixes. It never treats item quantities, proc probability or duration as stat amounts. Raw text, IDs and parsing diagnostics are preserved in dumps.

Critical conversion is calibrated from `GetCriticalStrikeChance(0/1/100/1000/current/current+1000)` on the running client. It validates slope, intercept and saturation before attributing percentage sources. No universal coefficient is hardcoded. The visible footer shows only the native total chance; rating, calibration and formula helper remain diagnostic data. If calibration is unavailable, source effects show unavailable rather than ratings under a percentage-only UI.

[Native champion data manager](https://github.com/esoui/esoui/blob/live/esoui/ingame/champion/championdatamanager.lua) initializes pending points to saved points. Therefore description/current-bonus calls receive the **saved total**, not zero or a delta. `CanChampionSkillTypeBeSlotted` handles both native slottable types. Active slots come from the committed champion bar. `GetChampionSkillJumpPoints` is captured; no stage is estimated from prose. Current bonus text alone supplies numeric contributions; a per-stage description is never used as a total.

Skills use purchased ability IDs at committed ranks and `GetSkillLineDynamicInfo`'s `isActive` result. Only complete unconditional passive clauses are generic rules. Conditional weapon, armor-count, slotted-skill and subclass interactions require an ID rule with an activation predicate; unsupported interactions remain candidates. Inactive skill lines and unpurchased abilities cannot contribute.

Effects are collected from the player, including foreign casts. Expiry is in seconds while game time is in milliseconds. `endTime=0` is permanent. `GetAbilityBuffType(id, "player")` identifies native named buff families, deduplicating identical Major/Minor buffs across ability IDs. Amounts and affected stats come from current descriptions, accommodating API 101051's merged buffs. Unknown stack rules are not multiplied by stack count.

Mundus membership comes from `GetUnitActiveMundusStoneBuffIndices`, independent of localized names. Values use native `GetAbilityDerivedStatAndEffectByIndex`, as exposed for Mundus stats, with no further Divines multiplication. Food classification uses the observed effect-ID mapping maintained by [LibCombat's author](https://github.com/solinur/LibCombat); unidentified food still appears as a generic effect if its current flat clause is recognized.

The additive percentage group applies to recognized **raw flat** resource/damage sources with a verified base. Raw committed attribute contributions are included; already effective native Mundus contributions are excluded. Supported recovery percentages now apply to the verified recovery base plus recognized raw flat sources. This is deliberately a partial attribution: percentage effects on unknown flats, special multiplicative sets, offhand scaling, conditional armor/skill bonuses, curse and environment scaling remain in `Unknown`. No inverse calculation assigns the remainder to a fabricated source. Each percentage row stores its exact numeric base in the dump.

The two-column table displays the numeric contribution and percentage; the exact multiplication base, slot/rank/CP details and source evidence remain in dumps. Known contributions use compensated summation and largest-remainder rounding: round their raw subtotal once, floor individual values, then allocate the missing units by descending fractional parts, with stable source-order ties. For 3148 + 14% + 20%, the raw total is 4218.32 and displayed rows total 4218, avoiding the old independently-rounded 4219. A genuine integer excess still produces Unknown -1. Compensated summation also preserves the exact half-unit total 3007.5 in the tank fixture; no rounding epsilon or residual-dependent tolerance is used. Raw amounts, `rawExplained` and `rawUnknown` remain in the dump. Rounded-zero rows are omitted from the display; captured sources and contributions remain available.

Generic passive contributions sharing an ability ID and stat with an emitted active-effect contribution defer to the active effect. Distinct ability IDs and unrelated stat clauses are preserved. Native nilable results remain nilable; required collection counts and numeric results are validated before traversal. Category collectors are isolated so malformed metadata does not abort the character snapshot.

The native [keyboard stat tooltip](https://github.com/esoui/esoui/blob/live/esoui/ingame/stats/keyboard/zo_statentry_keyboard.lua) supplies the original localized title, description and display value. The addon prehooks only its 15 recognized main stats. Text and sources share one private ZO_BaseTooltip inside TooltipTopLevel, matching [native templates](https://github.com/esoui/esoui/blob/live/esoui/ingame/tooltips/tooltips.xml). The shared InformationTooltip is never modified. [Native ClearTooltip](https://github.com/esoui/esoui/blob/live/esoui/ingame/tooltips/tooltips.lua) preserves content during fade; the view releases controls on hiding/clearing, not on mouse exit.

Width uses source-cell measurements only, floored at the untouched native default maxX (350 UI units), bounded by the screen. Header/description and attribute preview wrap inside it. Height and width use hidden native Label:GetTextDimensions probes without reading previous tooltip dimensions or scaling the block. A refresh with unchanged width preserves height/scroll; changed source width recalculates height to accommodate title wrapping. Visible labels are assigned final dimensions only, and unchanged title/description text is not rewritten. All text uses ZoFontHeader, as in native character stat labels.

API 101051 documents GetTextDimensions as returning UI units and GetStringWidth as returning a scaled native width. Natural width uses a zero-width probe; wrapped height uses the target width and a generous height, avoiding a constrained visible label's metrics. [Native ZO_TooltipSection:AddCustomLabelInternal](https://github.com/esoui/esoui/blob/live/esoui/libraries/zo_tooltip/tooltip.lua) likewise sets width and reads GetTextDimensions. The scaled nature of GetStringWidth is also confirmed by [ZOS staff](https://www.esoui.com/forums/showthread.php?t=1831), post12; the addon does not use it as an unscaled dimension setter input.

Equipment/set icons come from GetItemLinkIcon; passive/effect icons come from native skill/buff metadata. CP uses the discipline ID/type and the same green/blue/red point-pool icons as [ZO_ChampionDisciplineData:GetPointPoolIcon](https://github.com/esoui/esoui/blob/live/esoui/ingame/champion/championdatamanager.lua). The discipline index and star ability ID do not determine the colour.

Base rows use the native character-menu icon. Attribute rows use `/esoui/art/characterwindow/Gamepad/gp_characterSheet_{health,magicka,stamina}Icon.dds`, identical to KanaWardrobe/EffectModel.lua's info-panel metrics.

## Verified passive additions in 1.0.5

ID 185239 (Erudition) is recognized only by its complete native RU/EN unconditional description, including its flavor sentence. The percentage comes from that text; a conditional tail or foreign ID does not qualify. The generic parser still stops at unknown prose.

ID 29397 (Sword and Board) requires a captured native PRIMARY/BACKUP hotbar category consistent with the front/back bar and weapon pair, known active main/offhand slots, a native one-handed axe/hammer/sword/dagger in the main hand and a shield in the offhand. Its full current RU/EN description supplies the damage percentage; purchased and active-line checks remain required. An inactive shield, dual wield, staff, two-handed weapon, werewolf bar or missing metadata cannot activate it.

The latest dump #3 has `DONT_APPLY_BONUS` critical ratings 2181, while conversion of the documented 10% gives 2191.2. No primary evidence establishes the cause or guarantees this API value is the pure critical base, so both -10 rating residuals remain (about -0.05%). Nothing reassigns this discrepancy to a guessed source. See [analysis and evidence](2026-10-06-confirmed-sources.md).

Native PRIMARY/BACKUP enums are now captured explicitly. A category-change event invalidates current context without dropping equipment/build caches. Legacy 1.0.4 snapshots lack those enums, so offline replay supplies the existing collector test API enum metadata; the serialized fixture itself is unchanged. A legacy snapshot with no supplied enum metadata conservatively retains the 73 damage residual. Runtime code never hardcodes or infers these enums.
