# Основания правил KanaTrifecta

API и штатный интерфейс: [ESO UI, API 101051](https://github.com/esoui/esoui/tree/6639eb2adecc0480557d9068579319919a0c3fe6), срез 2026-09-28. Сигнатуры death state, combat event, power update, zone changed и выдачи достижений сверены с `ESOUIDocumentation.txt`.

Зоны, лимиты, условия начала и каталог ID достижений: [Raidificator 4.8.1.1](https://www.esoui.com/downloads/info1101-Raidificator.html), `Zones.lua` и классификация `Achievements.lua`. Каталог достижений upstream сгенерирован на API 101051 2026-08-05. Используются данные, без зависимости от установленного Raidificator и без копирования его UI.

Профили имеют статус `partial`, пока правила не подтверждены в целевом клиенте. Исторический прогресс достижений используется для чтения текстов и каталога, но не как прогресс текущего прохождения.

Диагностика выключена по умолчанию. `/ktri debug on` собирает ограниченные нормализованные события и исходные признаки текущей активности; `/ktri dump` помещает их в SavedVariables. Данные не отправляются наружу. Они записываются клиентом при штатном сохранении.

Коралловое гнездо: основные встречи Малигалиг, Саридил, Вараллион сверены с `DungeonStrats/DungeonStratsData.lua`. Для Вараллиона `CrutchAlerts/bosshealthbar/DungeonThresholds.lua` содержит точные `vetHealth=6766879` и `hmHealth=13195414`. Проверяется равенство, без выдуманного порога или переноса на другие встречи. Здоровье, не совпавшее ни с одним значением, не доказывает обычный режим. Для Малигалига и Саридил пока нет проверенного признака HM: после убийства строка остаётся неизвестной.

Убийство привязано к именованному `bossN` и явному мёртвому состоянию единицы либо к именованной цели явного боевого результата смерти уже наблюдавшегося пула. Исчезновение тега и нулевое здоровье сами по себе не засчитываются. Начало предполагает наблюдавшийся переход всей группы из другой зоны и отсутствие уже начавшегося боя; позднее присоединение остаётся неизвестным. Это клиентские наблюдения, а не серверный ID инстанса или таймер достижения.

## General catalogue

`profiles/catalog.lua` contains 58 veteran group dungeons with a speedrun limit in Raidificator's zone table. IDs and bit flags are decoded from its achievement classifier (V=1, conqueror=2, HM=4, speed=8, no-death=16, trifecta=32, final encounter=64). This inventory is source-bounded, not proof that no newer dungeon exists. Normal dungeons, trials, arenas and zones without a sourced limit are excluded.

Boss-name/order metadata comes from the installed DungeonStrats `DungeonStratsData.lua`; strategy prose is not copied. Native zone names are read from the current client. Additional Russian boss names and nine pairs of exact veteran/HM maximum-health values come from CrutchAlerts `lang/default.lua`, `lang/ru.lua`, and `bosshealthbar/DungeonThresholds.lua`. A missing health match never establishes normal mode. A single explicitly-final HM achievement establishes the final encounter's requirement; ambiguous multi-HM attribution stays unknown.

Fungal Grotto I's missing Russian names are cross-checked against the [Russian conqueror achievement criteria](https://eso-hub.com/ru/achievements/zavoevatel-gribnogo-grota-i): Тазкад Вожак Стаи, Вождь Озозай, Мать выводка, Щелкун. The existing CrutchAlerts name for Кра’гх remains. A localization regression verifies all five display names and boss-death matching in both Russian and English; other profiles may still fall back to English where sourced Russian names are absent.

The common observer and data catalogue replace 57 duplicated profile files. This is a implementation-plan adjustment to keep identical logic in one module; it does not replace per-dungeon client acceptance. `COVERAGE.md` records that all 58 profiles remain partial. Encounter metadata can include optional encounters and cannot certify server-defined speed/no-death windows until compared with current client criteria and recorded runs.

The native skull texture `esoui/art/icons/mapkey/mapkey_groupboss.dds` is referenced by CrutchAlerts `drawing/AttachedIcons.lua`. The HM and achievement icons use Lucide [scroll-text](https://github.com/lucide-icons/lucide/blob/main/icons/scroll-text.svg) and [award](https://github.com/lucide-icons/lucide/blob/main/icons/award.svg), matching the mockup. Original SVGs and the ISC license are in `textures/`; `build.cjs` exports white, transparent 64x64 classic BGRA DDS files for native colour tinting. The achievement medal displays at 22x22, matching the nominal keyboard quest icon size, with separate white hover/pressed states. The texture render, font shadow, scrolling and exact geometry still need a client check.

Native quest anchor is resolved through `FOCUSED_QUEST_TRACKER:GetTrackerControl()` ([ESO questtracker.lua](https://github.com/esoui/esoui/blob/6639eb2adecc0480557d9068579319919a0c3fe6/esoui/ingame/zo_quest/questtracker.lua)), with `WINDOW_MANAGER:GetControlByName` as fallback. A dynamically created named child is not assumed to have a matching exported Lua global.

Quest-yellow comes from `GetInterfaceColor(INTERFACE_COLOR_TYPE_CON_COLORS, CON_APPROPRIATE)`, the same colour family used by quest headers via `GetConColor` ([defaultcolordefs.lua](https://github.com/esoui/esoui/blob/6639eb2adecc0480557d9068579319919a0c3fe6/esoui/libraries/globals/defaultcolordefs.lua)). The native scroll viewport reserves `ZO_SCROLL_BAR_WIDTH` at its right ([scrolltemplates.xml](https://github.com/esoui/esoui/blob/6639eb2adecc0480557d9068579319919a0c3fe6/esoui/libraries/zo_templates/scrolltemplates.xml)); the addon places this reservation outside the shared text edge.

Raidificator `Zones.lua` defines start rule -1 as an undetectable threshold with first engagement as its substitute; `Status.lua` maps it to rule 0. Its observer registers `EVENT_PLAYER_COMBAT_STATE` and checks `IsUnitInCombat("player")` immediately when activating dungeon mode. `StartTimer` assigns the start only once. Positive rules start at the matching subzone, with boss engagement as a fallback; Unhallowed Grave starts on `EVENT_COMBAT_EVENT`, ability 131774, `ACTION_RESULT_EFFECT_GAINED`. KanaTrifecta implements these rules in its existing observer/model, without copying the upstream UI or saved-variable implementation.

KanaTrifecta additionally permits first observed combat when previous history is unknown, including late entry or a reload without a recoverable start. In Fungal Grotto I the display waits at 15:00, then counts down from the first observed combat; leaving combat or observing enemy deaths is unnecessary. This is a local fallback, not the achievement's exact tunnel-crossing threshold. Both fallback start and unknown history retain estimated quality and unknown start uncertainty internally; the HUD displays plain numbers. The estimate alone never confirms achievement success or failure. An already running or stopped clock is not restarted.

Timer hover uses a private native `TooltipTopLevel` → `ZO_BaseTooltip` and `AddControl` for a measured two-column table; its body is anchored with `CENTER` inside the native cell. Shared `InformationTooltip` remains untouched. Fonts `ZoFontGame` / `ZoFontGameBold` come from the checked native font definitions. Only the timer has a HUD tooltip. Boss kill labels derive elapsed time from the already-recorded kill and start timestamps; existing reload rebasing preserves that offset. Optional LibAddonMenu-2.0 exposes the account-wide display preference, with slash commands available without it.

Boss-death fallbacks use the checked API results `ACTION_RESULT_KILLING_BLOW`, `ACTION_RESULT_DIED`, and `ACTION_RESULT_DIED_XP`; LibCombat also registers result-filtered death handlers and uses the target name/unit ID from `EVENT_COMBAT_EVENT`. KanaTrifecta requires a matching active boss pull and enemy target type for combat deaths, and retains these subscriptions after removing start-only observers. An explicit boss-tag death can use the last observed identity after the tag disappears. Matching normalizes apostrophe variants and uses native case folding without changing display names. None of these death observations establishes hard mode.

Fungal Grotto I: [UESP Kra'gh NPC data](https://en.uesp.net/wiki/Online:Kra%27gh_the_Dreugh_King), fetched through the MediaWiki API on 2026-10-11 (page 177559), lists veteran maximum health 3,993,959 and hard-mode maximum health 4,593,053. The profile uses these exact values with the existing in-combat `GetUnitPower` observation; current remaining HP is irrelevant. Any other maximum stays unknown rather than implying a missing HM. The same observer handles native boss deaths and combat-result death fallbacks. These published values still need verification in the target client; they are not an ESO API guarantee.
