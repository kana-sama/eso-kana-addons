# KanaTrifecta

Предварительная версия панели для трифекты в ветеранских групповых подземельях ESO (API 101051). Для работы панели внешние библиотеки не нужны; меню настроек использует необязательную LibAddonMenu-2.0.

Панель закреплена под штатным квест-трекером: название, обратный отсчёт, смерти группы, список встреч. Овертайм отсчитывается вверх красным; смерти становятся красными отдельно. Подтверждённое убийство без обязательного HM красит босса красным, подтверждённое выполнение — штатным цветом успеха. Неизвестный режим остаётся приглушённым. Свиток обозначает наличие HM; галочек, крестиков и надписи HM нет.

Часы останавливаются по последнему подтверждённому конечному убийству всех встреч профиля, даже если забег уже провален. Они не ждут ачивку или сдачу квеста. Список встреч вне отдельного пилотного профиля пока требует проверки обязательности: необязательные и многосоставные встречи подробно оговорены в [COVERAGE.md](COVERAGE.md).

## Установка

Папка уже находится в `AddOns/eso-kana-addons/KanaTrifecta/`, как остальные аддоны репозитория. Включить **KanaTrifecta** в списке дополнений ESO и выполнить `/reloadui`. Отдельного пакета библиотек не требуется.

## Достоверность

Это рабочая реализация с частичным покрытием, а не принятый релиз. Каталог содержит 58 данжей из проверенного источника; полный актуальный каталог клиента ещё не сверён. Ни один профиль не объявлен полностью проверенным. Подробная таблица — [COVERAGE.md](COVERAGE.md), основания — [SOURCES.md](SOURCES.md).

- До старта показывается неподвижный лимит: в Грибном гроте I — `15:00`. Для недоступного порога стартует первый наблюдавшийся бой, как в Raidificator. При неизвестной истории входа/reload первый наблюдавшийся бой запускает локальный отсчёт в любом поддержанном данже. Проверяется и бой, уже активный при загрузке UI; запасной сигнал — положительный урон игрока/участника в том же инстансе. Повторный бой не сбрасывает часы.
- `--:--`: нет известного лимита или после завершения неизвестен итог времени.
- `~19:50`: время восстановлено приблизительно по интервалу секундных часов после `/reloadui`. Локальный запасной старт отображается обычным числом, качество расчёта хранится в модели. Погрешность пропущенного начала неизвестна: визуальный овертайм не доказывает провал ачивки. Для свежего контекста сохраняются известные пороги подзоны и специальное событие Unhallowed Grave; бой с боссом служит запасным стартом при пропущенном пороге подзоны.
- Счётчик смертей показывает только наблюдавшиеся смерти обычным числом, начиная с `0`, без `?` и `≥`. Полнота истории остаётся внутренним признаком; пропущенные смерти не выдумываются.
- При переходе всей группы из другой зоны без истории этого данжа допускается локально наблюдавшийся новый старт. Возврат в ранее наблюдавшийся данж остаётся неопределённым: API не предоставил надёжный ID нового инстанса.
- `/reloadui` восстанавливает текущие факты по одноразовой отметке, совпадению зоны/профиля/состава группы. Замороженный таймер сохраняется; незавершённый пул HM сбрасывается в неизвестный. Перезапуск игры или неоднозначный возврат не приравниваются к reload.
- HM распознаётся только по точным проверенным максимальным HP, без предположения «события HM не было — значит обычный режим». Для Малигалига и Саридил в Коралловом гнезде признака HM пока нет. Для Вараллиона есть точные значения вет/HM.
- Исторические ачивки не превращают текущих боссов в выполненные. Кнопка возле заголовка читает актуальные статусы клиента; отдельная категория открывается в журнале, смешанная — в собственном штатном списке по точным ID.
- Остановка времени и окно смертей независимы. Пока конец no-death окна не подтверждён, наблюдение смертей продолжается. Дополнительные враги и условия остаются неопределёнными; аддон не объявляет полную трифекту по трём зелёным строкам.

Панель скрывается вне подходящего ветеранского данжа и в режиме геймпада. Состояние продолжает обновляться в меню. Вне данжа снимаются боевые подписки и обновление HUD. Каталог ачивок не сканируется на каждом tick.

## Настройки

В меню дополнений → KanaTrifecta доступно «Показывать время убийства боссов» (включено по умолчанию). Слева от убитого босса отображается фиксированное `мм:сс` от начала таймера; для HM-встреч между временем и именем остаётся свиток. Без наблюдавшегося старта метка не выдумывается. Настройка действует сразу и сохраняется для аккаунта. Без LibAddonMenu доступны `/ktri bosstimes on` и `/ktri bosstimes off`; `/ktri settings` открывает установленное меню настроек.

Тултип есть только у таймера: две колонки и три строки — лимит, прошедшее время, остаток или превышение. Название, смерти, боссы, свитки и кнопка достижений не показывают подсказок.

## Диагностика

Диагностика выключена по умолчанию. Команды отвечают в чат только по явному вызову:

- `/ktri status` — текущий профиль, зона, сложность, сцена, режим ввода и состояние HUD: скрытие, якорь, координаты, размеры, наличие отрисованных данных.
- `/ktri debug on` / `/ktri debug off` — запись последних 512 событий и исходных признаков.
- `/ktri dump` — экспорт журнала и снимка в `KanaTrifectaState.dump` в SavedVariables. ESO пишет файл при штатном сохранении, выходе или reload; аварийное завершение не гарантирует запись.

Никаких сетевых отправок и автоматических сообщений группе нет.

## Проверки

Поведенческие сценарии и весь Lua синтаксис проверяются на Lua 5.1:

```sh
python3 -m venv /tmp/kana-trifecta-tests
/tmp/kana-trifecta-tests/bin/pip install lupa==2.8
/tmp/kana-trifecta-tests/bin/python KanaTrifecta/tests/run51.py all
```

Команда запускается из корня репозитория. Она проверяет модель, события, сохранение, каталог, сцены и структуру контролов через адаптер; это не подтверждение отрисовки ESO.

Клиентская приёмка ещё нужна: один `/reloadui`, затем свежий ветеранский вход, привязка при коротком/длинном/пустом квесте, RU/EN, меню/HUD/геймпад, список с малой доступной высотой, кнопка достижений с прежним поиском/фильтром, смерть/вайп/HM, последний босс до/после лимита и reload до/после остановки. Запись первого прохода: включить debug перед входом, после прохода вызвать dump и reload. Неизвестные HM и серверные окна уточняются по этим записям, а не по догадкам.
