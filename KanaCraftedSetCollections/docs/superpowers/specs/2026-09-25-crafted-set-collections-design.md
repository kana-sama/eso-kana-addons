# KanaCraftedSetCollections: крафтовые сеты в коллекции

Дата: 2026-09-25  
Статус: реализовано; визуальная правка по скриншоту пользователя от 2026-09-25

## Цель

Показывать крафтовые сеты внутри штатной вкладки ESO «Коллекция сетов», в существующих разделах локаций. Игрок должен находить сет через обычное поле поиска, видеть его бонусы и требования к изготовлению. Аддон добавляет справочные записи в интерфейс; игровую коллекцию и возможность реконструкции он не меняет.

## Источник данных и зависимости

- Обязательная зависимость — установленный отдельно **LibSets**. Аддон использует её публичные функции для списка крафтовых сетов, локализованных названий, примерного предмета, числа требуемых изученных особенностей, зон и связи зон с категориями коллекции.
- В частности, используются `GetSetTypeSetsData(LIBSETS_SETTYPE_CRAFTED)`, `GetSetName`, `GetSetItemId`, `buildItemLink`, `GetTraitsNeeded`, `GetZoneIds` и `GetItemSetCollectionToZoneIds`.
- Собственной таблицы `setId → название/локация/требования` нет. При обновлении ESO новые записи поступают с обновлением LibSets.
- Координаты станций и метки на карте не используются.

## Размещение и поиск

1. Каждый крафтовый сет из LibSets сопоставляется с разделами коллекции по всем его зонам. Если зон несколько и им соответствуют разные разделы, сет показывается в каждом из них. В пределах одного раздела дублей нет.
2. Поддерживаются существующие разделы **локаций**. Сеты не помещаются в разделы подземелий, испытаний или арен по совпадению идентификаторов или родительских зон.
3. Если ни одной зоне сета не соответствует раздел локации в штатной коллекции, сет показывается в дополнительном разделе «Другие места крафта». Это единственный запасной раздел, а не основной способ группировки.
4. Текущее поле поиска коллекции ищет крафтовые сеты по локализованному названию без учёта регистра. При поиске остаются видимыми родительский и дочерний разделы локации, если в них есть совпавший крафтовый сет, даже когда штатный поиск не нашёл игровых сетов. Внутри раздела показываются только совпадения. Сброс поиска восстанавливает полный список.
5. Обычные сеты продолжают отображаться и фильтроваться штатным способом. Если поиск совпал и с обычными, и с крафтовыми сетами одной локации, видны оба вида записей.

## Карточка крафтового сета

В списке локации каждый крафтовый сет представлен заголовком и **одним** примерным предметом, выбранным из LibSets. Предмет даёт обычную подсказку с бонусами набора. Заголовок содержит только название сета; под ним отдельной строкой показано «Требуется N изученных особенностей». Это число является требованием сета, а не проверкой исследований текущего персонажа.

Примерный предмет визуально имеет состояние **«собрано»**: цветная иконка без затемнения, как у разблокированных предметов. Это не означает, что предмет внесён в серверную коллекцию ESO. Полоса прогресса, цена реконструкции, действие реконструкции, её кнопка и двойной щелчок для такого предмета отсутствуют. Правый щелчок может оставлять обычное действие «Ссылка в чат».

Кнопки карты в заголовке нет.

## Связь со штатным интерфейсом

Надстройка работает с клавиатурной версией окна `Collections → Sets`. Она добавляет собственные отображаемые записи в существующие категории и отслеживает то же поле поиска. Данные крафтовых карточек хранятся в отдельной модели представления; аддон не добавляет их в `ITEM_SET_COLLECTIONS_DATA_MANAGER`, не вызывает для них `IsItemSetCollectionSlotUnlocked` и не записывает искусственные состояния в SavedVariables.

Счётчики и проценты собранности существующих категорий остаются показателями **игровой** коллекции. Крафтовые карточки выглядят собранными, но не меняют числитель или знаменатель этих счётчиков. При открытии того же интерфейса на станции трансмутации справочные записи скрыты и недоступны для реконструкции.

Индекс крафтовых сетов строится после готовности LibSets и переиспользуется при поиске и переключении категорий. UI-код изолирует обработку крафтовых записей от штатных обработчиков плиток и заголовков: нативные функции стоимости, собранности и реконструкции для них не вызываются. Если после обновления клиента нужная точка подключения интерфейса недоступна, надстройка не меняет штатный список и сообщает об ошибке один раз за сессию.

## Границы первой версии

- Поддерживается клавиатурный интерфейс ESO на PC/Mac. Геймпадный интерфейс требует отдельной адаптации.
- Поиск крафтовых сетов в штатном поле — по названию. Поиск по бонусам не входит в первую версию.
- Карта и маркеры станций не добавляются.
- Аддон не отслеживает, какие части крафтового сета физически лежат у персонажа, в банке или сундуках.
- Если LibSets не содержит новый сет либо его зону, надстройка не придумывает запись или координаты. Сет с известным названием, но без сопоставленной категории попадает в запасной раздел.

## Проверка при реализации

Проверка в игре обязательна, поскольку успешная загрузка Lua не доказывает правильное поведение штатного окна.

1. В категории локации с обычными и крафтовыми сетами оба вида видны одновременно; у крафтового сета один предмет с цветной иконкой и корректной подсказкой.
2. Поиск по русскому названию крафтового сета показывает нужную категорию и карточку, в том числе если совпадений в игровой коллекции нет. Поиск по обычному сету работает как прежде.
3. Сет с несколькими зонами появляется в каждой подходящей категории один раз. Сет без подходящей категории находится в «Других местах крафта».
4. Полная строка требования видна под названием; у крафтового заголовка нет полосы прогресса и кнопки карты. При повторном использовании заголовка обычным сетом штатные элементы восстановлены.
5. Крафтовая карточка не предлагает реконструкцию ни через щелчок, ни через контекстное меню; на станции трансмутации её нет.
6. Прогресс категорий и итоговый прогресс остаются равны значениям штатной коллекции. Переключение категорий, очистка поиска и повторное открытие окна не оставляют чужих строк или элементов управления.

## Техническое основание

Штатная вкладка строит категории и список из `ITEM_SET_COLLECTIONS_DATA_MANAGER`, а её текстовый поиск индексирует только игровые ID коллекции. Поэтому одного добавления `setId` в поисковый индекс недостаточно: надстройка должна расширить **отображение** категорий и списка, сохранив игровые данные отдельно. LibSets уже предоставляет API для крафтовых сетов, зон и соответствующих категорий.
