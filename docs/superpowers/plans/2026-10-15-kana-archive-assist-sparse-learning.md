# KanaArchiveAssist: обучение на редкой истории

> Execution: superpowers:executing-plans, текущая сессия. Пользователь прямо поручил сначала симуляцию, затем переработку; повторного согласования реализации не требуется.

**Goal:** показывать полезную информацию при 1–2 ранах по две арки ежедневно; скрывать только способности без истории.

**Architecture:** общая и контекстная регуляризованные модели конкурируют с равномерным выбором на исключённых целых ранах. После выбора весов оба эксперта обучаются на всей прошлой истории. История, capture, профили и геометрия остаются прежними; неизвестность контекста ограничивает силу, не видимость.

**Tech:** ESO Lua, L-BFGS, standalone Lua tests, независимый NumPy Newton, Python stdlib для отчёта.

**Spec:** [текущая спецификация](../specs/2026-10-15-kana-archive-assist-design.md).

## Ограничения

- Никакого push. До первого push весь новый аддон остаётся одним коммитом через `jj squash`.
- Семь плоских меток и расположение не перерисовываются; `/kaa`, прокрутка, маленькое окно, capture сохраняются; прежняя пауза позже заменена флажком учёта одного предложения.
- Один выбор — одно наблюдение. История версии 1 сохраняется, модели типов и профилей разделены.
- Статистика — реальные наблюдения с явными знаменателями. Уверенность и точность не выдумываются.
- Неизвестный вариант не становится проигравшим, новые стеки не скрывают известные варианты.

## Review focus

- Неизвестный третий вариант не должен менять смесь, используемую для сравнения известных.
- Только один известный вариант должен сохранять осмысленную положительную/отрицательную опору.
- Возобновлённые старые раны после контрольной границы не попадают в калибровочное обучение.
- Изменяющиеся секции тултипа не наследуют ширину и выравнивание чужих pooled labels.
- Качество симуляции оценивается по видимым меткам, без скрытого argmax при одинаковых шевронах.

## Задачи

- [x] До изменения продукта проверить прототип на 111 реальных IDs, последовательных выборах и полном накапливающемся контексте. Seed17 — только исследование параметров. Зафиксировать плохой результат отрицательных контролей, не выдавать его за успех.
- [x] RED → GREEN: cold start, перенос на новый контекст/соперника, частично известная тройка, ограничения силы, циклы/контекст, старая история.
- [x] Удалить bootstrap и жёсткий support; добавить фактические индексы. `GetPerkStats(dataset,offer)` → статистика каждого известного варианта; `ContextSupport.NewJob` → `byId.maxLevel`, без запрета нового контекста.
- [x] RED → GREEN: калибровка против равномерного выбора на случайном безразличии, lone-known baseline, известная пара + неизвестный третий, хронологическое отсечение возобновлённого рана.
- [x] `ChoiceModel.NewFitJob` возвращает base/context и веса uniform/base/context; `Predict` возвращает utilities для известного поднабора и полные вероятности для NLL. Для ≥4 ранов последняя четверть целых ранов исключена из проверочных fit, затем оба эксперта переобучены на всей прошлой истории.
- [x] RED → GREEN: статистика без точного совпадения, переменные секции тултипа, ошибка support job, оценка одинаковых зелёных меток без скрытых scores.
- [x] Провести 30 финальных экспериментов: 4 отдельных seeds ×7 сценариев ×60 ранов; дополнительно полностью двухвариантные/трёхвариантные предложения. Первые два рана обновлять после каждого выбора, далее между ранами. Не исключать холодный старт или участок смены привычки.
- [x] Сохранить воспроизводимый отчёт по дням: наличие любой информации, доля предложений с зелёным вариантом, качество таких советов и случайного выбора, ошибки направлений, равенство, NLL относительно общего рейтинга. Слабые результаты сохранить явно.
- [x] Выполнить полный набор аддона, независимый численный эталон, синтаксис, whitespace и порционный performance stress. Получить независимое ревью; исправления сохранить в том же неопубликованном коммите.

## Команды

```sh
lua KanaArchiveAssist/tests/run.lua
lua KanaArchiveAssist/tests/benchmark.lua stable 73 mixed > /tmp/kaa-final-stable-73.csv
python3 KanaArchiveAssist/tests/simulation_report.py /tmp/kaa-final-*.csv --output KanaArchiveAssist/tests/simulation-report.md
lua KanaArchiveAssist/tests/performance.lua
```

Полный default `benchmark.lua` выполняет 28 основных экспериментов и пишет один CSV. Для дополнительных двух режимов seed101 выполнить `stable 101 two` и `stable 101 three` в отдельные CSV. Клиент ESO отдельно проверяет события, визуальное размещение и фактическое время порций; локальный стенд этого не доказывает.

## Итог

57 тестов; 3 независимые численные фикстуры; 30 финальных экспериментов и 54 000 выборов. Сырые агрегаты сохранены в `tests/fixtures/simulation-results.csv`, отчёт воспроизводится без повторного fit. Четыре критерия скорости старта/качества/безразличия пройдены. Ограничения по резкому развороту привычек и клиентской производительности явно оставлены в README и отчёте. Независимое ревью исправлено через RED/GREEN; клиентская приёмка ESO не выполнена.

Дополнительная граница: редкий перк, выпавший из 2000-окна, сохраняет метку с архивными фактами; только действительно отсутствующий в полной истории ID скрывается. Проверено RED/GREEN на2001 наблюдении. Индекс архивных фактов обновляется при записи, полного пересканирования истории при каждом предложении нет.

Последующее изменение интерфейса: квадратный флажок слева от постоянной подписи `учитывать выбор` в нижнем правом углу экрана, вне окна селектора и над полосой игровых действий, заменяет паузу. По умолчанию галочка установлена; её снятие исключает одно предложение. Состояние принадлежит одному offerId и фиксируется при подтверждении. Соседние профили/прокрутка/расположение перков сохранены; см. актуальную спецификацию.
