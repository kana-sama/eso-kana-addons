# KanaCombatBookmarks Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans for inline execution, or superpowers:subagent-driven-development if the user chooses delegation. Steps use checkbox syntax.

**Goal:** Ставить закладки биндом, узнавать случайное запоминающееся имя из углового уведомления и переходить к яркому разделителю в центре лога CMX.

**Architecture:** Отдельные метаданные боя сохраняются стандартным кодом CMX. Адаптер жизненного цикла связывает метки с боями; представление объединяет отфильтрованные события и разделители, не меняя исходный лог.

**Tech Stack:** Lua 5.1, ESO controls/XML bindings, Combat Metrics 1.7.8, CombatMetricsFightData 22, LibCombat 89.

**Spec:** [Спецификация](../specs/2026-10-17-kana-combat-bookmarks-design.md).

## Global Constraints

- Зависимости: `CombatMetrics>=10708 CombatMetricsFightData>=22 LibCombat>=89`; API `101050 101051`.
- Реальное время нажатия, 48 случайных имён из пула спеки без повторов до исчерпания; затем суффиксы `· 2`, `· 3`. Имя неизменно после сохранения. Угловое уведомление через `ZO_AlertNoSuppression(UI_ALERT_CATEGORY_ALERT, nil, message)` только после записи плюс один непосредственный `PlaySound(SOUNDS.LOCKPICKING_CHAMBER_LOCKED)` — короткий щелчок; то же имя в списке и ярко-золотом разделителе строго в центре.
- Сохранить фильтры, прокрутку, страницы, копирование, переключение боёв и доступность при малом окне; не менять файлы CMX и исходный `fight.log`.
- Один изменяемый jj-коммит на весь новый аддон до первого push; push не выполнять.

## Review Focus

- Смерть/конец боя и немедленный новый бой: метка не попадает к соседнему бою — Task 1.
- Исчерпание пула, отказ записи и загрузка: имена уникальны, не теряются и не меняются; повторные хуки не дублируют уведомления — Tasks 1–3.
- Все события скрыты фильтрами или сохранены без лога: различать эти состояния — Task 2.
- Граница 1000 строк, переносы, малая высота и края боя: разделитель остаётся в центре — Task 2.
- Чужое изменение UI или отсутствующий контрол: штатный CMX не ломается — Tasks 2–3.

### Task 1: Запись и сохранение

**Files:** `KanaCombatBookmarks/Names.lua`, `Model.lua`, `Integration.lua`, `tests/support.lua`, `tests/test_names.lua`, `tests/test_bookmarks.lua`.

**Interfaces:** `Names.New(randomInt, existingEntries) -> generator`, `generator:Next() -> name`; `Model.Add(entries, offsetMs, name) -> entry`; `Integration.Install(api) -> adapter`; `adapter:Mark() -> entry|nil, reason`; `adapter:GetViewedFight() -> fight|nil`. Поле хранения и структура записи — как в спеке. Генератор создаётся один раз для боя; имя запрашивается после проверки возможности записи.

- [x] Написать тесты имён с подставным RNG: ровно 48 уникальных названий из JSON спеки, первые 48 выборов без повторов, следующие 48 с `· 2`, продолжение с существующими записями без коллизий. Запустить `lua KanaCombatBookmarks/tests/test_names.lua`; подтвердить падение, затем реализовать локальный пул и перемешивание Fisher–Yates в `Names.lua`, указав источники.
- [x] Написать тесты записи: один вызов — одна метка; точные миллисекунды и имя; смерть, финализация, сброс, новый бой; после конца разрешено `<=10000 ms`, позже отказ; выключенная подробная запись; одинаковые timestamps. Успешная запись вызывает один штатный alert с сохранённым именем и один `PlaySound(SOUNDS.LOCKPICKING_CHAMBER_LOCKED)`; alert получает `soundId=nil`, чтобы не удваивать звук. Отказ не расходует имя, не сообщает об успехе и не издаёт щелчок; два быстрых нажатия дают два уведомления и два вызова звука.

Присоединять метаданные до возможного сохранения; не использовать индекс истории как идентификатор.
- [x] Добавить round-trip через CombatMetricsFightData: имена и метки сохраняются даже после изменения пула, исходные события неизменны, загрузка не удваивает записи и не вызывает уведомление о создании или звук. Учесть Lua 5.1-синтаксис установленного LibDataEncode в стенде.
