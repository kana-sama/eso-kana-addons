# KanaTrifecta Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Создать нативную панель трифекты под квест-трекером ESO: время, смерти группы, обязательные боссы с результатами HM и переход к достижениям текущего данжа.

**Architecture:** События клиента проходят через наблюдатель и проверенный профиль данжа в чистую модель забега. Модель отделяет убийство от результата HM, остановку часов от завершения остальных условий, а факты от неизвестных данных. HUD показывает готовое представление; сохранение и диагностика используют снимок той же модели.

**Tech Stack:** Lua 5.1, штатные контролы и сцены ESO, SavedVariables, Python + `lupa.lua51` для локальных проверок. Внешних обязательных библиотек у игрового аддона нет.

**Spec:** [Утверждённая спецификация, версия 1.2](../specs/2026-10-11-kana-trifecta-design.md). Визуальный эталон: [интерактивный макет](../specs/assets/2026-10-11-kana-trifecta-panel.html).

## Global Constraints

- «Аддон размещается в `eso-kana-addons/KanaTrifecta/`, использует Lua 5.1 и штатные контролы ESO».
- «Обязательные зависимости от Raidificator, CombatAlerts и других аддонов не нужны».
- «Первая версия интерфейса предназначена для режима клавиатуры и мыши PC/Mac».
- «Галочек, крестиков и буквенной подписи `HM` в строках нет».
- «Таймер останавливается в момент убийства последнего из всех боссов, необходимых для трифекты, независимо от смертей, превышения времени и результатов HM».
- «Панель не перетаскивается мышью и не сохраняет независимые экранные координаты».
- «Неизвестные данные не используют цвет успеха».
- «Панель ничего не объявляет в чат и не отправляет другим игрокам автоматически».
- Имена, тексты, размеры, цвета, границы времени и условия показаны в спеке; HTML не служит источником шрифтов или RGB для Lua.
- Коралловое гнездо — первый сквозной профиль. Полное покрытие целевых данжей остаётся отдельной обязательной частью работы, а не заменяется одним примером.
- Срез API в спеке: `101051`, исходники `6639eb2adecc0480557d9068579319919a0c3fe6`. Перед подключением событий сверить целевой клиент; поддерживаемые APIVersion объявлять по фактической проверке.
- Все пути ниже относительны корню `eso-kana-addons`. Соседние аддоны не изменять. Для коммитов использовать `jj` по `AGENTS.md`.

## Review Focus

1. Отложенный callback от прежней зоны или прежнего пула: не меняет текущий забег и не открывает чужие достижения. Проверки в задачах 3, 4 и 7.
2. Один персонаж одновременно виден через `player` и `groupN`, затем меняется порядок группы: смерть учитывается один раз. Проверки в задачах 2 и 3.
3. Все обязательные боссы убиты, одна строка красная или HM неизвестен: часы остановлены и остаются остановленными после reload. Проверки в задачах 1, 2 и 5.
4. Сцена HUD возвращается без активного данжа, якорь пересоздан или снизу мало места: нет вспышки панели, сохраняется привязка, доступен последний босс. Проверки в задаче 6.
5. Журнал сохранил поиск и фильтр, а категория смешивает несколько данжей: открывается полный список только текущего данжа. Проверки в задаче 7.

## Границы и порядок исполнения

План охватывает один продукт с общими профилями и моделью; отдельные подсистемы здесь не выпускаются как независимые аддоны. Задачи 1–2 дают проверяемую модель, 3–4 — установленный диагностический аддон и первый профиль, 5–7 — полноценный интерфейс и восстановление, 8–9 — покрытие и приёмку.

При реализации сначала определить, нужна ли изоляция текущей рабочей копии, и следовать `superpowers:using-git-worktrees`. Создание worktree не является частью подготовки этого документа. Изменения одной задачи сохранять одним scoped-коммитом; последующие исправления непубликованной задачи присоединять через `jj squash` по правилам репозитория.

Клиентские эксперименты нужны для проверки правил профилей. Если клиент недоступен, продолжать независимые модельные и UI-работы на фикстурах, оставляя профиль `partial`; не выдавать отсутствие игрового подтверждения за законченный релиз. Непроверенные ID, пороги здоровья и правила старта не угадывать.

### Типы

- `Context`: `runKey`, `contextGeneration`, `zoneId`, `difficulty`, `language` (`ru` или `en`, для остальных локалей английский fallback), `freshness` (`fresh`, `same`, `unknown`). Ключ забега локальный; одинаковый `zoneId` не доказывает одинаковый инстанс.
- `Observation`: `kind`, `key`, `contextGeneration`, `atMs`, `wallSec`, `payload`, `evidence`. `key` нужен для дедупликации; неизвестная временная метка допускается только с явно неизвестным качеством времени. Событие убийства сохраняет время исходного признака, если позднее подтверждение позволяет его установить.
- Виды наблюдений — строго список из спеки: `ContextEntered`, `RunStarted`, `MemberObserved`, `MemberDied`, `MemberRevived`, `CoverageLost`, `PullStarted`, `HardModeObserved`, `BossKilled`, `RunCompleted`, `ContextLeft`, `AchievementAwarded`.
- `Snapshot`: схема и версия, все поля модели из спеки, исходные подтверждения и качество данных. Его таблицы не должны разделять изменяемое состояние с моделью.
- `View`: `lifecycle`, `title`, `timer={text,colorRole,quality,elapsedMs,stopped}`, `deaths={text,colorRole,count,coverage}`, `bossRows={...}`, `assessment`, `failureReasons`, данные тултипов. `bossRows` — массив в порядке профиля; строка содержит `bossKey`, `name`, `hasHardMode`, `state`, `colorRole`, основание результата.
- `colorRole`: `normal`, `hint`, `success`, `error`; заголовок отдельно использует штатный цвет названия. Фактические объекты цветов принадлежат HUD.
- `Signal`: снимок или событие API с поколением контекста, исходным временем и исходными полями. Наблюдатель не меняет поколение задним числом, чтобы принять старое событие.

Не зависеть от `io.popen` внутри Lua. Пропускать отсутствующие будущие модули нельзя; список проверяемых модулей растёт вместе с задачами.

## Task 1: Профили, часы и остановка по всем обязательным боссам

**Files:** Create `Run.lua`, `Profiles.lua`, `tests/run51.py`, `tests/fixtures.lua`, `tests/test_clock.lua`, `tests/test_profiles.lua` внутри `KanaTrifecta/`.

**Interfaces:** `KanaTrifecta.Profiles:Register(profile) -> boolean, errors[]`; `:Find(zoneId, difficulty) -> profile|nil`; `:Validate(profile) -> errors[]`; `:List() -> profiles[]`. `KanaTrifecta.Run.New(profile, context) -> run`; `run:Apply(observation) -> changed`; `run:View(nowMs) -> View`; `run:Snapshot() -> Snapshot`.

Тестовая фикстура `F.NewRun(overrides)` создаёт свежий наблюдаемый контекст поколения 1 с лимитом `1500000`, правилом `atOrBefore` и тремя обязательными боссами `a`, `b`, `c`. `F.Emit(run, kind, payload, atMs, key)` создаёт наблюдение того же поколения; `F.Start(run, atMs)` и `F.Kill(run, bossKey, atMs)` сокращают только оформление событий. Килл содержит подтверждение конечной смерти; эти помощники не вычисляют ожидаемый результат модели.

- [ ] **Step 1:** Создать тесты `countdown_and_boundary`, `stops_after_all_required_kills`, `overtime_freezes`, `unknown_start_stays_unknown`, `profile_validation`. Основные утверждения:

  ```lua
  local run = F.NewRun()
  F.Start(run, 0)
  assert(run:View(300000).timer.text == '20:00')
  F.Kill(run, 'a', 400000); F.Kill(run, 'b', 800000)
  assert(run:View(1200000).timer.stopped == false)
  F.Kill(run, 'c', 1260000)
  assert(run:View(1800000).timer.text == '04:00')
  assert(run:View(1800000).timer.colorRole == 'normal')
  assert(run:View(1800000).timer.stopped == true)
  ```

  Другие проверки на отдельных фикстурах: `limit-1 -> 00:01`, `limit -> 00:00` обычный, `limit+1 -> 00:00` красный, `limit+1000 -> 00:01` красный; убийство всех на 30-й минуте фиксирует красный `05:00`. `deadlineRule=before` на точной границе делает обе цифры красными. Время больше часа не оборачивает минуты. Пустой список полного профиля и дубли `bossKey` не проходят валидацию; неполные метаданные разрешены как неполная поддержка. Профиль только с метаданными, без правил времени, смертей и встреч даёт `--:--`, `?`, без выдуманных строк боссов; частичная неизвестность HM не отменяет уже проверенные часы.
